# BE:A COMPANY — Design System

> 목적: 완료된 메인페이지의 실제 HTML/CSS/JS를 기준으로 서브페이지를 제작할 때 브랜드 정체성과 UI 규칙을 일관되게 유지하기 위한 문서.
>
> 적용 범위: `Beacompany/` 프로젝트. 기준 파일은 `index.html`, `css/main.css`, `js/main.js`이며, 공통 초기화 규칙은 `../css/default.css`, Pretendard 선언은 `../font/css/pretendardvariable.css`에서 확인한다.
>
> 원칙: 이 문서는 기존 디자인을 바꾸기 위한 제안서가 아니다. 아래에 적힌 값은 코드에서 확인한 값이며, 코드에서 확인되지 않은 값은 임의로 보충하지 않는다.

## 1. Project overview

BE:A COMPANY 웹사이트는 예술·공간·브랜드 기획 및 디렉팅 프로젝트를 소개하고, 방문자가 회사의 전문 분야와 대표 작업을 파악한 뒤 프로젝트 문의로 이어지게 하는 포트폴리오형 사이트다.

메인페이지 콘텐츠 흐름은 다음과 같다.

1. **Hero / Featured projects** — 대표 프로젝트 이미지, 프로젝트명, 분야·연도, 슬라이더 이동 기능으로 시각적 인상을 먼저 전달한다.
2. **About / What We Do** — “ART & SPACE EXPERIENCE.” 소개 문구와 SPACE, ART, BRAND, CONSULTING 네 가지 업무 영역을 설명한다.
3. **Signature Work** — 대표 프로젝트를 이미지와 간단한 메타데이터로 보여준다.
4. **Partners** — 파트너 관련 콘텐츠 영역.
5. **Wanna Contact?** — 관심 분야를 선택하고 프로젝트 문의를 시작하도록 유도한다.
6. **Footer** — 회사 위치, 전화, 이메일, 소셜 계정, 개인정보처리방침, 저작권 정보를 제공한다.

**디자인 방향:** 검정과 흰색을 기반으로 한 고대비, 영문 대문자 제목, 넓은 이미지, 단순한 구획, 얇은 선과 절제된 장식으로 예술·공간 프로젝트를 강조한다. 일부 콘텐츠 영역에는 밝은 배경을 사용해 섹션 사이의 대비를 만든다.

## 2. Brand identity

### 시각적 특징

- **모노크롬 기반:** 핵심 색은 블랙과 화이트이며 회색은 보조 텍스트·경계선에 사용한다.
- **영문 타이포그래피 중심:** ABOUT, WHAT WE DO, SIGNATURE WORK, PARTNERS, WANNA CONTACT?처럼 영문 대문자를 주요 제목과 내비게이션에 사용한다.
- **이미지 우선:** Hero와 Signature Work에서 프로젝트 이미지가 콘텐츠의 핵심 역할을 한다. 이미지 비율과 잘림 방식은 기존 컴포넌트 규칙을 따른다.
- **정돈된 정보 계층:** 큰 제목 → 설명 또는 프로젝트 메타데이터 → 링크/CTA 순서로 정보를 읽게 한다.
- **기하학적 UI:** 둥근 슬라이더 컨트롤, pill 형태의 연락 버튼·태그, 둥근 서비스 카드 등 컴포넌트별로 정해진 모서리 형태를 사용한다. 모든 요소에 같은 radius를 적용하지 않는다.
- **노란색은 제한적으로:** `--color-yellow: #F5C400` 변수가 정의되어 있고 Hero 프로젝트 링크의 밑줄에 사용된다. 다른 영역의 기본 강조색으로 확대하지 않는다.

브랜드 성격을 나타내는 표현은 ‘절제된’, ‘이미지 중심의’, ‘현대적인’, ‘전문적인’이다. 이는 코드와 콘텐츠 구성에서 읽어낸 디자인 해석이며, 별도의 공식 브랜드 가이드에서 확인한 문구는 아니다.

## 3. Design principles

1. **메인페이지를 시각적 기준으로 삼는다.** 서브페이지에서도 배경 전환, 제목 위계, 이미지 중심 구성, 여백의 리듬을 이어간다.
2. **기존 CSS 변수를 우선 사용한다.** 색상을 새로 하드코딩하기 전에 `:root` 변수를 확인한다.
3. **콘텐츠 위계가 먼저다.** 제목, 설명, 메타데이터, CTA의 크기와 명도 차이를 유지한다.
4. **반복 UI는 재사용한다.** 같은 역할의 버튼·태그·카드에 페이지마다 다른 모양을 만들지 않는다. 단, Hero 컨트롤과 서비스 태그처럼 목적이 다른 요소는 각각의 기존 규칙을 유지한다.
5. **프로젝트 이미지의 존재감을 유지한다.** 임의의 장식, 과도한 그림자, 불필요한 테두리로 이미지보다 UI가 먼저 보이게 하지 않는다.
6. **인터랙션은 명확하고 절제되게 한다.** 현재 슬라이더의 이동·opacity 변화와 링크 hover 등 기존 움직임의 속도와 성격을 따른다.
7. **기존 메인페이지는 수정하지 않는다.** 서브페이지 전용 마크업과 스타일을 추가하고, 공통 스타일을 수정해야 한다면 메인페이지에 영향이 없는지 먼저 검증한다.

## 4. Color system

### 확인된 CSS 변수

| 변수명 | 값 | 사용 기준 |
|---|---|---|
| `--color-black` | `#0A0A0A` | 기본 어두운 배경, 어두운 섹션, 검정 텍스트의 기준 |
| `--color-white` | `#FFF` | 어두운 배경 위 텍스트 및 밝은 UI |
| `--color-gray` | `#666` | 보조 텍스트 등 회색 계열의 기준 변수 |
| `--color-yellow` | `#F5C400` | Hero 프로젝트 링크의 강조 밑줄 |
| `--font-primary` | `"Futura PT", "Pretendard Variable", sans-serif` | 본문 전반의 폰트 스택 |

### 실제 CSS에서 함께 사용하는 색상

| 코드 | 사용 위치/용도 |
|---|---|
| `#0a0a0a` | 헤더, Hero 및 어두운 섹션 배경. 변수 값과 동일한 색을 일부 규칙에서 직접 사용한다. |
| `#050505`, `#080808` | 연락 섹션의 텍스트 및 선택 UI 일부 |
| `#fff` / `#ffffff` | 밝은 배경과 텍스트 |
| `#aaa`, `#999`, `#777`, `#666` | 보조 문구, 메타데이터, 푸터 텍스트 등 |
| `#e5e5e5`, `#d0d0d0`, `#d9d9d9`, `#bdbdbd` | 카드 테두리, 구분선, 이미지 플레이스홀더 등 |
| `#ffffff29`, `#ffffff05` | 헤더 경계선 및 버튼의 낮은 불투명도 배경 |
| `#f8e7a6` | 연락 분야 선택 상태의 배경. 노란색 변수와는 다른 실제 사용값이다. |

**적용 규칙**

- 기본 페이지 배경은 섹션 역할에 따라 블랙 또는 화이트를 선택한다. 메인페이지의 실제 흐름처럼 어두운 Hero, 밝은 소개·프로젝트 영역, 어두운 Partners, 밝은 Contact, 어두운 Footer의 대비를 참고한다.
- 본문과 제목은 배경과 충분히 대비되는 색을 사용한다.
- 보조 설명과 프로젝트 메타데이터는 회색으로 위계를 낮추되 읽기 어려울 정도로 흐리게 하지 않는다.
- 새 컬러를 임의로 추가하지 않는다. 기존에 없는 상태색이 필요하다면 먼저 디자인 근거를 검토하고 메인페이지와의 일관성을 확인한다.
- 변수 값과 직접 작성된 HEX 값이 혼재되어 있다. 서브페이지 구현에서는 의미가 같은 기존 색상 변수를 우선 사용하되, 메인페이지 CSS를 대규모로 정리하거나 변경하지 않는다.

## 5. Typography

### 폰트

- 기본 폰트 스택: `--font-primary: "Futura PT", "Pretendard Variable", sans-serif`
- 프로젝트 폴더에 Futura PT 계열 폰트 파일이 있다. CSS에서는 Futura PT를 우선 지정하고 Pretendard Variable을 대체 글꼴로 지정한다.
- Pretendard Variable은 `../font/css/pretendardvariable.css`에서 선언되며, 해당 파일은 `font-display: swap`을 사용한다.
- 영문 제목과 내비게이션은 Futura PT의 특성을 살리고, 한글 문장은 폴백 폰트가 자연스럽게 표시되도록 한다.
- 개별 `font-weight`는 요소마다 다르므로 모든 제목을 동일한 굵기로 통일하지 않는다.

### 실제 CSS에서 확인한 주요 타이포그래피

| 요소 | 크기 규칙 | 굵기 / 행간 / 기타 |

### 타이포그래피 적용 방법

- 큰 영문 제목은 섹션을 빠르게 인식시키는 역할을 하므로 큰 크기와 굵기를 유지한다.
- 프로젝트명 아래의 분야·연도는 제목보다 작고 회색으로 처리해 보조 정보로 구분한다.
- 한글 설명은 크기뿐 아니라 `line-height: 1.5` 수준의 여유를 활용해 읽기 편하게 한다.
- 위 표는 현재 코드에서 확인한 대표값이다. 다른 요소에 동일한 수치를 기계적으로 적용하지 말고, 역할이 가장 가까운 기존 요소를 기준으로 삼는다.

## 6. Layout & spacing

### 컨테이너

- Header: `width: min(1720px, calc(100% - 40px))`; 가운데 정렬.
- About 콘텐츠: `width: min(1720px, 100%)`; 섹션 좌우 패딩으로 화면 여백 확보.
- Signature Work / Partners / Contact: 기본 스타일에 `width: min(1626px, 100%)`가 있으나, 후속 CSS에서 일부 섹션이 `width: 100%; max-width: none`으로 재정의된다. 최종 적용값은 CSS에서 마지막에 선언된 규칙을 기준으로 확인한다.
- Header 높이: 데스크톱 `100px`, 900px 이하 `76px`, 560px 이하 `68px`.
- Footer와 하단 섹션은 Figma 조정용 후속 규칙에서 좌우 `5.4%`~`5.6%` 패딩을 사용한다. 모바일에서는 `18px`로 바뀌는 영역이 있다.

### 간격과 정렬

- 주요 컨테이너는 `margin: 0 auto`로 가운데 정렬한다.
- Header는 Flexbox의 `align-items: center`, `justify-content: space-between`으로 로고·내비게이션·문의 링크를 배치한다.
- About 서비스 카드는 데스크톱에서 4열 Grid(`repeat(4, minmax(0, 1fr))`), 900px 이하에서 2열이다.
- Signature Work 카드는 데스크톱 3열, 900px 이하 2열, 560px 이하 1열이다.
- 서비스 카드 내부는 Flexbox 세로 배치이며 `.service-tags { margin-top: auto; }`로 태그를 카드 하단에 정렬한다.
- Hero 슬라이더는 가로 Flex 트랙을 사용한다. JS가 현재 슬라이드 너비와 트랙 간격을 계산해 활성 프로젝트를 중앙에 배치한다.
- 간격값은 섹션별로 다르다. 예를 들어 About은 데스크톱 `padding: 110px 20px 120px`, 모바일 `64px 18px 72px`; Signature Work은 데스크톱 `110px 20px 120px`, 모바일 `64px 18px 72px`다. 모든 섹션에 하나의 패딩값을 강제하지 않는다.

### 이미지

- Hero 이미지: `object-fit: cover`; 너비는 `min(54.375vw, 1044px)`, 태블릿 이하 `78vw`, 모바일 `84vw`로 조정된다.
- Signature Work 이미지: `aspect-ratio: 512 / 590`, `object-fit: cover`; 상단 모서리만 둥글게 처리한다.
- 이미지에 의미가 있다면 적절한 `alt` 텍스트를 작성한다. 장식 이미지에는 불필요한 대체 텍스트를 반복하지 않는다.

## 7. Components

### Header / GNB

- 클래스: `.site-header`, `.header-inner`, `.brand-mark`, `.main-nav`, `.contact-link`
- 로고는 왼쪽, GNB는 가운데 영역, Contact 링크는 오른쪽에 둔다.
- 데스크톱 로고 크기 `73 × 51px`; 900px 이하 `58 × 41px`.
- GNB 간격은 데스크톱 `55px`, 900px 이하 `22px`, 560px 이하 `14px`다.
- Contact 링크는 테두리 1px의 pill형이며 데스크톱 높이 `43px`, 900px 이하 `36px`, 560px 이하 `32px`다.
- 현재 HTML의 GNB는 About, What We Do, Signature Work, Partners 앵커로 구성된다. 서브페이지에서는 정보 구조에 맞게 항목을 조정하되 로고·메뉴·Contact의 배치 원칙을 유지한다.

### Hero 프로젝트 슬라이더

- 클래스: `.hero-sec`, `.visual`, `.visual-track`, `.project-slide`, `.project-image`, `.project-caption`, `.visual-controls`, `.visual-pagination`
- 비활성 슬라이드는 `opacity: .5`, 활성 슬라이드는 `opacity: 1`이다.
- 이전/다음 버튼은 원형 테두리 컨트롤이며, 페이지네이션은 비활성 점과 활성 가로 막대로 상태를 구분한다.
- JS에서 3개 원본 슬라이드의 앞뒤에 복제 슬라이드를 배치해 순환 이동을 구현한다. 슬라이드 개수를 변경할 때는 JS의 원본 개수 검사와 인덱스 처리도 함께 검토한다.

### Service card

- 클래스: `.service-cards`, `.service-card`, `.service-number`, `.service-copy`, `.service-tags`
- 데스크톱 카드: 최소 높이 `600px`, 패딩 `50px 28px 36px 32px`, 테두리 `1px solid #e5e5e5`, radius `24px`.
- 번호는 `68 × 68px` 검정 원 안에 흰색으로 표시한다. 모바일에서는 `56 × 56px`.
- 태그는 얇은 회색 테두리의 pill형이다. 여러 개일 때 줄바꿈할 수 있도록 Flexbox의 `flex-wrap: wrap`을 유지한다.

### Signature Work card

- 클래스: `.signature-grid`, `.signature-card`, `.signature-image`, `.signature-caption`
- 이미지 위, 프로젝트명 아래, 분야·연도 메타데이터 순서로 구성한다.
- 이미지 상단 모서리 radius는 데스크톱 `24px 24px 0 0`, 태블릿 이하 `18px 18px 0 0`이다.
- 카드 사이 간격은 데스크톱 `45px`, 900px 이하 `20px`, 모바일 세로 목록에서는 `36px`다.

### Contact selector / CTA

- 클래스: `.contact-options`, `.contact-fields`, `.contact-option`, `.contact-cta`
- 분야 선택은 실제 radio input을 사용하고, 선택된 항목에는 `.is-selected`를 적용한다.
- 옵션은 최소 높이 `42px`, 좌우 패딩 `18px`, 1px 테두리, `2px` radius다.
- 선택 상태 배경은 `#f8e7a6`; 체크된 라디오에는 검정 배경과 흰 체크 표시를 사용한다.
- 문의 CTA는 검정 텍스트의 밑줄 링크로 표시한다. 기존 메일 주소나 외부 링크 목적지는 임의로 복사하지 말고, 서브페이지 목적에 맞는 내부 경로 또는 실제 문의 수단을 연결한다.

### Footer

- 클래스: `.site-footer`, `.footer-inner`, `.footer-logo`, `.footer-company`, `.footer-legal`
- 어두운 배경과 회색의 작은 텍스트를 사용하며, 로고·회사 정보·정책/저작권 정보를 구분한다.
- 연락처는 전화·이메일·소셜 링크를 제공할 수 있다. 실제 프로젝트에 맞는 링크만 연결하고 존재하지 않는 정책 페이지나 주소를 임의로 만들지 않는다.
- 모바일에서는 컬럼이 세로로 쌓이도록 한다.

### 링크 원칙

- **외부 브랜드 사이트로 연결하지 않는다.** 서브페이지 제작 시 링크는 프로젝트 내부의 실제 페이지, 페이지 내 앵커, 실제 문의 수단으로 연결한다.
- 기존 HTML에 외부 소셜 링크가 있어도 새로운 서브페이지에 무조건 복사하지 않는다.
- 링크처럼 보이지만 목적지가 없는 `#`를 최종 링크로 남기지 않는다. 실제 목적지가 아직 없다면 작업 중임을 주석으로 표시하고 배포 전에 해결한다.

## 8. Interaction

- 페이지 내부 앵커 이동은 CSS의 `html { scroll-behavior: smooth; }`를 따른다.
- Hero 트랙 이동은 `transform` 전환 `650ms ease`; 활성 슬라이드의 opacity 전환은 `250ms ease`다.
- 페이지네이션은 `width`와 `background`를 `200ms ease`로 전환한다.
- Contact CTA hover는 `background 180ms ease, color 180ms ease`로 변화한다. 실제 최종 CSS에서 해당 CTA가 텍스트 밑줄형으로 재정의되어 있으므로, 최종 표시 상태를 기준으로 서브페이지 적용 여부를 판단한다.
- About 드롭다운 관련 규칙이 CSS에 존재한다면 `:hover`와 `:focus-within`에서 메뉴가 열린다. 현재 제공된 HTML에는 해당 드롭다운 마크업이 보이지 않으므로, 마크업에 없는 드롭다운을 새 페이지에 임의로 추가하지 않는다.
- `../css/default.css`의 `:focus-visible`은 `2px solid currentColor`, `outline-offset: 2px`다. 키보드 사용자의 포커스를 알아볼 수 있도록 유지하고 포커스 표시를 제거하지 않는다.
- 공통 초기화 파일은 `prefers-reduced-motion: reduce`에서 애니메이션과 전환 시간을 줄인다. 새로운 모션도 이 접근성 설정을 존중한다.
- 버튼·링크는 마우스뿐 아니라 키보드와 터치 환경에서도 사용할 수 있어야 한다. 상태를 색상만으로 구분하지 말고, 필요하면 체크 표시·크기 변화 등 보조 단서를 함께 둔다.

## 9. Responsive rules

현재 CSS의 주요 breakpoint는 **900px**와 **560px**다. 서브페이지도 기존 breakpoint를 우선 사용하고, 새 breakpoint를 추가해야 한다면 실제 레이아웃이 깨지는 지점을 근거로 결정한다.

### 900px 이하

- Header 높이와 로고·내비게이션·Contact 링크 크기를 줄인다.
- Hero 슬라이드 너비를 `78vw`로 조정하고 이미지 높이를 화면 너비에 맞춰 제한한다.
- 서비스 카드를 4열에서 2열로 바꾼다.
- Signature Work를 3열에서 2열로 바꾼다.
- Contact 등 하단 영역의 컬럼 수와 간격을 줄인다.

### 560px 이하

- Header 높이는 `68px`; GNB 간격과 Contact 링크 크기를 더 줄인다.
- Hero 슬라이드는 `84vw`; 캡션은 세로 방향으로 정렬한다.
- 서비스 카드는 2열을 유지하되 내부 패딩·최소 높이·타이포그래피를 축소한다.
- Signature Work는 1열 목록으로 전환한다.
- 하단 섹션과 Footer는 좁은 좌우 여백(`18px`)을 사용하고, Footer 정보를 세로로 쌓는다.

### 반응형 제작 체크

- 가로 스크롤이 생기지 않는지 확인한다.
- 제목과 버튼이 겹치지 않는지, 긴 영문 프로젝트명이 컨테이너를 넘치지 않는지 확인한다.
- 카드 높이를 고정할 때는 작은 화면에서 콘텐츠가 잘리지 않는지 확인한다.
- 터치 조작에 충분한 버튼 영역을 확보한다.
- `100svh`를 사용하는 Hero는 모바일 브라우저의 주소창 변화도 고려해 테스트한다.

## 10. Do & Don't

### Do

- 기존 메인페이지의 색상·타이포그래피·여백·이미지 처리·섹션 대비를 기준으로 서브페이지를 설계한다.
- 기존 CSS 변수 `--color-black`, `--color-white`, `--color-gray`, `--color-yellow`, `--font-primary`를 먼저 확인한다.
- 같은 역할의 UI는 기존 컴포넌트 규칙을 재사용한다.
- 섹션 제목, 설명, 메타데이터, CTA 사이에 명확한 위계를 둔다.
- 기존 breakpoint인 `900px`, `560px`에서 반응형을 먼저 확인한다.
- 키보드 포커스, 라디오 선택 상태, 모션 감소 설정을 지원한다.
- 내부 페이지는 프로젝트 내부의 상대 경로 또는 실제 내부 앵커로 연결한다.
- CSS를 수정하기 전에 해당 규칙이 메인페이지에 미치는 영향을 확인한다.

### Don't

- 기존 메인페이지 디자인을 변경하거나, 서브페이지 작업을 이유로 기존 스타일을 무단 재정의하지 않는다.
- 근거 없이 새 브랜드 컬러, 폰트, breakpoint, 컨테이너 너비, radius, 애니메이션 시간을 만들지 않는다.
- 모든 카드와 버튼에 같은 radius를 강제하지 않는다.
- 과도한 그림자, 장식용 그라디언트, 임의의 아이콘 세트를 추가해 기존의 절제된 시각 체계를 흐리지 않는다.
- 영문 제목을 임의로 다른 폰트나 지나치게 가는 굵기로 바꾸지 않는다.
- 실제로 존재하지 않는 페이지나 외부 브랜드 사이트를 링크 대상으로 만들지 않는다.
- `:focus` 표시를 없애거나, hover만으로 중요한 기능을 이용할 수 있게 만들지 않는다.
- 현재 HTML에 구현되지 않은 기능을 문서상 이미 구현된 것처럼 설명하지 않는다.

## 구현 시 주의사항

- `css/main.css`에는 같은 선택자에 대한 여러 차례의 후속 재정의가 있다. 예를 들어 Partners, Contact, Footer는 초기 규칙 뒤에 별도의 조정 규칙이 추가되어 있다. **실제 화면에서 적용되는 값은 CSS에서 나중에 선언된 규칙과 미디어 쿼리의 우선순위를 함께 확인해야 한다.**
- HTML과 CSS 사이에 일부 불일치가 있다. 문서 작성 시 확인된 클래스와 실제 최종 렌더링을 구분하고, 새 페이지에서는 실제 마크업과 연결되는 선택자를 사용한다.
- 이 파일은 디자인 기준 문서이며, 기존 HTML/CSS/JS의 변경이나 리팩터링을 수행하지 않는다.
